DeepLearnLib

C++/CUDA library for training and inference, written for a Bachelor's thesis. The core does not link LibTorch. Tensors, layers, and SGD run on CUDA, cuBLAS, and cuDNN. LibTorch is optional and is linked only by the *_torch comparison programs.

Convolution, max-pooling, and the GRU go through the cuDNN C API. A fully-connected layer multiplies with matmul_into (cuBLAS, TF32) and adds the bias in a separate CUDA kernel. Leaky ReLU, cross-entropy, and the SGD step are small CUDA kernels. There is no autograd graph and no Thrust in the core: each layer implements forward and backward itself. Output buffers are kept for a repeated shape instead of calling cudaMalloc on every step.

Layout

include/DeepLearnLib/ public headers (core, layers, losses, loaders, utils)
src/ the same folders, compiled into libDeepLearnLib
benchmarks/models/ SimpleCNN, TabularMLP, GruClassifier (DeepLearnModels)
benchmarks/train/ paired train_*_custom and train_*_torch programs
benchmarks/forward/ forward-latency programs
benchmarks/micro/ operator micro-benchmarks
benchmarks/common/ shared config, batch, and metrics helpers
tests/ GoogleTest program dllib_tests
config/ experiments.json, sanity.json
scripts/ dev.sh, dev.ps1, menu.sh, plots, cloc, coverage
docs/doxygen/html/ API reference generated by Doxygen
reports/ cloc, coverage, and the last measured epoch

Gru is part of the core. The three application networks are not.

API reference

The generated reference is docs/doxygen/html/index.html. It is built from the Doxygen comments in include/DeepLearnLib/ and benchmarks/models/. After a comment change, regenerate it from the repository root:

doxygen Doxyfile

Polish install and build steps are in INSTALL.md.

Build

Requirements: CMake 3.18+, Ninja, a C++17 compiler, CUDA with nvcc, cuBLAS, and cuDNN. OpenCV is required for the image loaders and the benchmarks/ programs. Without it, CMake still builds the core and the tests that do not decode images.

cmake -S . -B build -G Ninja -DUSE_CUDA=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
./build/tests/dllib_tests

Configure reads nvidia-smi and sets CMAKE_CUDA_ARCHITECTURES to <major><minor>-real, so the driver does not JIT PTX. Timings use Release. DEBUG_NUMERICS=ON checks for NaN and Inf after a layer and synchronises the device, so leave it off for a measured run.

Docker:

docker compose up -d --build
docker exec -it deeplearn_dev_container bash
./scripts/dev.sh

On Windows, powershell -File scripts/dev.ps1 loads the Visual C++ environment and then runs Git Bash. Do not call WSL bash.exe: nvcc will not see the MSVC headers. Set CUDNN_ROOT and OpenCV_DIR before configuring. Details are in INSTALL.md.

Run

scripts/menu.sh groups training and forward passes by dataset (CIFAR-10, MNIST, tabular, ECG200), then micro-benchmarks and plots. Each custom binary has a Torch twin (train_cifar_custom / train_cifar_torch, and the same pattern for MNIST, tabular, and GRU).

The sanity entry points EXPERIMENTS_JSON at config/sanity.json (two epochs). Thesis numbers come from config/experiments.json.

A training run appends one row per epoch to results/<experiment>/metrics_custom.csv or metrics_torch.csv, with columns Epoch, LR, TrainLoss, TestLoss, TrainAcc, TestAcc, Time(s), and VRAM_MiB. Plot with:

python3 scripts/plot_metrics.py --results-root results

python3 scripts/freeze_measurements.py copies the last row of each metrics file to reports/measurements.md.

Tests, coverage, and line counts

dllib_tests is the GoogleTest binary. On 23 Nov 2026 the Release executable from 17 Oct 2026 passed 147 of 147 tests on the measurement machine. Cases that need a GPU are skipped when nvidia-smi fails.

reports/coverage.md maps each library, model, and shared header to the test file that names it (49 of 66 files, 74.2%). Line and branch rates come from lcov after a GCC/Clang Debug build:

cmake -S . -B build_coverage -G Ninja -DUSE_CUDA=ON -DCMAKE_BUILD_TYPE=Debug -DENABLE_COVERAGE=ON
cmake --build build_coverage --target dllib_tests
./build_coverage/tests/dllib_tests
lcov --capture --directory build_coverage --output-file coverage.info --rc lcov_branch_coverage=1 --ignore-errors gcov,source
lcov --extract coverage.info '*/src/*' '*/include/*' '*/tests/*' '*/benchmarks/models/*' '*/benchmarks/common/*' \
--output-file coverage.filtered.info --rc lcov_branch_coverage=1
python3 scripts/coverage_report.py --lcov coverage.filtered.info

ENABLE_COVERAGE does nothing under MSVC. CI runs this job without a GPU, so device-only lines stay uncovered there. The hosted summary is the lcov-coverage artifact of the Debug job.

Line counts from cloc 2.06 are in reports/loc.md. Regenerate with powershell -File scripts/loc.ps1. Kernel sources use the .cpp extension and are compiled as CUDA; the report splits those files using DEEPLEARN_CUDA_SOURCES.
